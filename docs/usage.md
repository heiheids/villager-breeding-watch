# 村民繁殖观测（Villager Breeding Watch）· 使用说明

## 一、这是什么
一个 Minecraft Java 版 26.3 的 Fabric 模组，用来回答一个问题：
**这些村民为什么生 / 为什么不生？**

它做四件事：
1. 村民头顶显示稳定编号与状态（`#12 ♥` 能生 / `#12 ✕ 缺食物3点` 不能生）；
2. 把村民和它绑定的床用彩色射线连起来，一眼看出床会不会在夜里被丢掉；
3. 右键村民打开详情页：食物、床、作息、配对对象、全部条件逐条打分；
4. 统计全图的出生 / 失败 / 死亡，失败还记原因（缺床、床走不到、求爱超时、被打断……）。

界面中英文双语，跟随游戏语言，也能手动切换。

作者：黑山大叔
主页：https://space.bilibili.com/19428259


## 二、版本与依赖

模组有**两个加载器版本**，功能一致、版本号统一为 **1.1.0**，按你用的加载器选一个装：

| 文件 | 加载器 | 依赖 |
|---|---|---|
| `villager-breeding-watch-fabric-26.3-1.1.0.jar` | Fabric | Fabric Loader 0.19.5+、Fabric API（26.3 任一版本）、Java 25 |
| `villager-breeding-watch-neoforge-26.3-1.1.0.jar` | NeoForge | NeoForge 26.3.0.67+（26.3.0.86 实测）、Java 25 |

- Minecraft：26.3（客户端与服务端都要装；单人游戏自动满足）
- Java：25（26.x 的运行时要求，启动器自动满足）
- 模组 id：`villagerbreedingwatch`（两个版本相同，**不能同时装**）
- 两个版本的配置文件、统计数据格式完全一致，换加载器后老存档可继续沿用

### 两个版本的唯一功能差异：头顶名牌

| | Fabric 版 | NeoForge 版 |
|---|---|---|
| 头顶显示 | 原版名字 + **另加一行** `#12 ♥ 可繁殖` | **直接替换**原版名牌为 `#12 ♥ 可繁殖 原版名字` |

原因：NeoForge 26.3 提供 `RenderNameTagEvent`（可替换名牌内容），
Fabric 侧**没有**等价钩子（已逐个扫描全部 fabric-api jar 确认），
只能用 `Gizmos.billboardTextOverMob` 额外画一行。这是引擎能力差异，不是实现取舍。


## 三、安装
1. 按加载器选对应的 jar，放进实例的 `mods\` 目录：
   - Fabric：`villager-breeding-watch-fabric-26.3-1.1.0.jar`
   - NeoForge：`villager-breeding-watch-neoforge-26.3-1.1.0.jar`
2. 启动游戏，进入任意世界。首次运行会生成：
   - `config\villagerbreedingwatch\lang\zh_cn.json` 与 `en_us.json`（可自行编辑）
   - `config\villagerbreedingwatch\client.json`（客户端设置）
   - 每个世界单独一份统计：`saves\<世界名>\villager_breeding_watch.json`
3. 卸载：删掉 jar 即可。配置文件与统计保留，重装后接着统计
   （村民编号按 UUID 稳定，不会重排；统计文件名与 1.21.1 旧版一致，老存档可直接沿用）。


## 四、按键（默认，可在「控制 → 按键绑定 → 村民繁殖观测」里改）
- V：打开设置界面
- B：打开统计界面
- N：总开关（开 / 关整套观测，并把状态同步给服务器）


## 五、设置界面里有什么
- 总开关：整套观测的总闸
- 头顶名牌：是否在村民头上显示 `#编号 ♥/✕ 缺什么`
- 床绑定射线：是否画村民到床的线
- 穿透显示：射线和头顶文字是否隔墙可见
- HUD 面板：左上角的信息面板
- 常开所有射线：不限半径，最多 600 名村民都画线
- 常开所有头顶信息：不限半径，全部村民都计入观测
- 扫描半径 / 刷新间隔（刻）：非「常开」模式下的扫描范围与频率
- 重载语言：改完语言文件后立刻生效
- 语言模式：在「跟随游戏语言」与「强制 zh_cn / en_us / 其他已安装语言」之间循环
- 底部：打开统计、完成

窗口较窄（或 GUI 比例较大）时，界面自动从两列改成单列依次排列，
避免两列重叠导致「点到的开关不是看到的那个」。


## 六、看什么、怎么看
1. 头顶名牌
   形如 `#12 ♥ 可繁殖` 或 `#12 ✕ 缺食物3点`。
   #后面是稳定编号（与统计页、详情页一致）；♥ 表示硬性条件都满足，✕ 表示不满足并给出最主要的缺失项。

2. 村民—床射线（颜色由服务器数据决定）
   - 绿色：正常绑定（床存在、可达、16 格内、是它自己的）
   - 橙色：这张床有「夜间会被丢弃」的风险，或不是该村民所有
   - 灰色：床距离超过 16 格（原版 HOME 校验范围外，繁殖时不认）
   - 橙红色：服务器判定这张床不可达
   - 红色：HOME 床已经不存在（被拆 / 被抢 / 未加载）
   - 实线：该床会被保留；虚线：夜间寻路时会丢弃这张床
   - 没有 HOME 的村民：青色虚线指向最近的空闲床
   - 床的位置会画一个小方框，方便在方块堆里找到它

3. HUD 面板（左上角）
   第一行是开关状态（含「常开射线 / 常开名牌」是否生效、半径、间隔），
   第二行是图例，第三行是 `观测 N 名（可繁殖 M 名）`，
   常开时追加「（常开：不限半径，上限600）」，并显示「服务器扫到 K 名」；
   数据超过刷新间隔 + 6 刻没更新会显示「（数据已停止更新）」。

4. 详情页
   右键村民：没有交易的村民直接进入详情页；有交易的村民会先打开交易界面，
   左下角多一个「繁殖详情」按钮（点它进详情页），原版交易流程不受影响。
   详情页显示：职业 / 等级 / 编号、食物与背包食物点、绑定床与候选床（含丢弃风险与原因）、
   距离下一个空闲期还有多久、当前作息、上次与本次配对对象与结果、
   全部硬性 / 软性条件的 ✔✘○ 列表（行尾有原因码）。支持滚轮翻页，「刷新」可重新拉取。

5. 统计界面
   三个标签：总览 / 失败明细 / 村民明细。
   - 总览：图例、总出生、总失败、总死亡、按原因统计、最近出生
   - 失败明细：每次失败的时间、村民编号、原因与详情
   - 村民明细：每个编号的村民出生了几次、现在是否在场


## 七、多语言
本模组有**两套**文案，各自负责不同界面（这点容易混，单独说明）：

1. **原版界面用的标准语言文件**（jar 内 `assets/villagerbreedingwatch/lang/`）
   负责「控制 → 按键绑定」里显示的分类标题和三个按键名。
   这一套是 mod 自带的，不需要你配置。

2. **模组自绘界面用的文案**（`config\villagerbreedingwatch\lang\`）
   负责设置 / 统计 / 详情三个界面的所有文字。
   - 自带 zh_cn 与 en_us，首次运行自动释放到该目录
   - 默认跟随游戏语言；想强制中文，在设置界面把「语言模式」循环到 zh_cn
   - 你也可以自己新建 `config\villagerbreedingwatch\lang\<语言代码>.json`（如 ja_jp.json），
     模组会自动加载；支持嵌套 JSON（会摊平成点号键），以 `_` 开头的键会被忽略（用来写注释）
   - 缺某个键时会退回内置默认，再退回键名本身，界面不会崩
   - 注意：用户文件里的键会覆盖 jar 内置文案。升级模组后想拿到新文案，
     可以把这两个文件删掉（进游戏会重新释放），或只改你需要自定义的那几行

   （可选）如果你想让「按键绑定」里的名字也换一种语言，需要改的是 jar 内那份标准文件，
   用资源包覆盖 `assets/villagerbreedingwatch/lang/<语言>.json` 即可，
   键名是 `key.villagerbreedingwatch.settings` / `.stats` / `.toggle`
   和 `key.category.villagerbreedingwatch.main`。


## 八、重要限制（如实说明，避免误判）
1. 头顶文字的**距离限制**是引擎决定的：只有客户端"已经拥有这个实体"时才画得出头顶文字，
   村民约 5 区块（≈80 格）内才会同步到客户端，超出就画不出来。
   远处的村民请看射线 / 详情页 / 统计页。
2. 头顶名牌的呈现方式两个版本不同：
   - **NeoForge 版**：用 `RenderNameTagEvent` 直接替换原版名牌内容，
     头顶只有一行 `#12 ♥ 可繁殖 原版名字`。
   - **Fabric 版**：Fabric 侧没有等价钩子（已逐个扫描全部 fabric-api jar），
     只能用世界空间文字额外画一行，于是头顶是「原版名字 + 本模组一行」。
     另一条路是自己写 mixin 改名牌渲染，风险与维护成本都高，没有采用。
3. 失败原因是**服务器侧推断**，不是原版事件：原版从不广播「这次繁殖为什么失败」。
   模组在生育窗口附近检查当时的条件（缺床 / 床不可达 / 对象丢失 / 求爱超时 / 睡觉 / 受惊 / 食物被吃），
   把最可能的原因记录下来。极端情况下可能标错，原因码可对照排查。
4. 床位 / POI 统计只覆盖已加载（且在模拟范围内）的区块；远处的床看不见。
5. 「常开」模式：服务器扫描不限半径但上限 600 名村民，扫描间隔不小于 20 刻（1 秒），
   每次扫描的寻路探测有预算限制，所以「床是否可达」是抽样探测的结果。
6. 联机时每个玩家各自一套开关与半径；统计数据是全服共享（按世界保存）。
7. 村民编号按 UUID 稳定，但从未被观测到过的历史村民不会补编号；出生序号按世界累计。


## 九、出问题怎么排查
0. **最快的办法：跑一次日志诊断脚本**（在 `源码\` 目录下执行）
   ```
   powershell -ExecutionPolicy Bypass -File tools\diag-log.ps1
   ```
   它按链路顺序检查：模组加载 → 客户端就绪 → 客户端发开关 → 服务端收开关
   → **服务端真的扫描了** → 客户端收到快照，第一次断在哪一步就报哪一步。

1. 也可以自己看 `logs\latest.log` 里以 `[VBW]` 开头的行，关键几行：
   - `[VBW] 已发送客户端开关给服务器：{...}`（客户端到底发了什么）
   - `[VBW] 收到 <玩家> 的开关：总开关=… 常开射线=… 常开名牌=… 半径=… 间隔=… 语言=…`
   - `[VBW] 扫描=N 名村民（常开=… 半径=… 上限=… 玩家维度=…）`
   - `[VBW] 快照 #N：本包 X 名 / 现有 Y 名，常开模式=…，维度=…`
   这几行足够判断是「服务器没扫到」还是「客户端没画」。
   注意：中文 Windows 上 latest.log 是 **GBK** 编码，用 UTF-8 打开会显示乱码，
   那只是显示问题，不是日志坏了。
2. HUD 第三行的「服务器扫到 K 名」是同一信息的即时版本。
3. 界面出现「等待服务器数据…」：
   - 若日志里**有** `扫描=N 名村民`：服务端在扫，是客户端没收到包（检查两端是否同版本 jar）。
   - 若日志里**没有** `扫描=N 名村民`：服务端根本没扫。历史上这个症状由两个 bug 引起，
     已在 1.1.0 修复：
       a) 用 `Long.MIN_VALUE` 当「从未扫描」哨兵，`now - last` 溢出成负数，永不扫描；
       b) 用维度时钟做节拍，下界/末地是固定时间维度（时钟恒 0），只扫一次。
     若仍复现，请把 `logs\latest.log` 发给作者。
4. HUD 显示「（数据已停止更新）」：超过「刷新间隔 + 6 刻」没收到新数据。
   在下界/末地若一直显示这一句，是 1.1.0 之前的开发版用世界时间判断导致的，已在 1.1.0 修复。
5. 界面上出现英文或键名：语言文件缺键，或语言文件是旧版本释放的副本（见第七节）。
6. 统计文件不存在不是错误，日志会写「统计文件不存在，将在退出时创建」。
7. 连服务器看不到数据：确认服务器也装了同一个 jar（模组是双侧的，服务端负责扫描）。


## 十、本包内容
- `villager-breeding-watch-fabric-26.3-1.1.0.jar`：Fabric 版（已装进 `26.3-Fabric000`）
- `villager-breeding-watch-neoforge-26.3-1.1.0.jar`：NeoForge 版（已装进 `26.3-NeoForge086`）
- `使用说明.txt`：本文件
- `技术说明.txt`：程序结构、关键 API 事实、数据格式、构建方式、双加载器差异
- `村民生育管理器-经验与踩坑.txt`：开发过程中值得记录的经验与踩坑（含事故复盘与双版本移植记录）
- `源码\`：Fabric 版完整工程
- `源码-NeoForge26.3\`：NeoForge 版完整工程（与 Fabric 版共用 17 个文件，仅加载器层不同）
  - 构建：`powershell -ExecutionPolicy Bypass -File tools\build.ps1`
  - 产物自检：`powershell -ExecutionPolicy Bypass -File tools\check-jar.ps1`
  - 源码防回归：`powershell -ExecutionPolicy Bypass -File tools\check-source.ps1`
  - 回归断言：`java tools\RegressionTest.java`
  - 日志诊断：`powershell -ExecutionPolicy Bypass -File tools\diag-log.ps1`
  （构建脚本会固定 JDK 25 与工程内的 GRADLE_USER_HOME，可离线构建）
